# 日常運用と障害対応

## 授業開始前

1. 公開URLを生徒へ配布する。
2. Vercelの `VITE_SUBMISSION_TO` が授業用メールになっていることを確認する。
3. Google Sheets の `PBL課題一覧` で、対象課題の `受付状況` を `受付中` にする。
4. Apps Scriptのトリガー一覧に `scanSubmissionMailbox` が存在することを確認する。

## 提出確認

1. `提出一覧` を最終提出日時の降順に並べる。
2. URLを開き、提出内容を確認する。
3. 再提出回数が2以上の生徒は、最終提出日時を採点対象として扱う。
4. `要確認` に行があれば、件名・URL・学校メールを生徒へ修正依頼する。

## 課題を追加・差し替える

1. Google Sheetsの `PBL課題一覧` に課題ID、テーマ、成果物、評価観点、提出方法、受付状況、表示順を追加する。
2. `app/src/content.js` に同じ `assignmentId` のカードを追加・編集する。
3. `cd app && npm run verify` を実行する。
4. GitHubへpushし、Vercelを本番デプロイする。

## 障害時

| 症状 | まず確認する場所 | 対応 |
| --- | --- | --- |
| メールが提出一覧に出ない | Gmailの件名・本文、`要確認` | 件名が `【WEB提出】課題ID｜学籍番号｜氏名`、本文に `URL: https://...` か確認 |
| 10分以上待っても処理されない | Apps Scriptのトリガー・実行履歴 | トリガーを再作成するため `setupSubmissionDesk` を実行 |
| 実行エラー | `_障害ログ` とApps Script実行履歴 | `SPREADSHEET_ID` とGoogle認可を確認 |
| 提出先メールを変えたい | Vercel Environment Variables | `VITE_SUBMISSION_TO` を変更し本番再デプロイ |
| 全生徒のメールが要確認になる | Script Properties | `ALLOWED_SENDER_DOMAIN` を学校ドメインへ修正、不要なら空欄にする |

## 学期末

1. Google Sheetsを複製して年度別に保管する。
2. Apps Script Propertiesの `SPREADSHEET_ID` を新しい管理表のIDへ差し替える。
3. `setupSubmissionDesk` を実行して新しい管理表のシート構成を準備する。
4. `app/src/content.js` と `PBL課題一覧` を次年度の課題へ更新する。
