# 新規セッション・新任担当者への引き継ぎ

## このリポジトリだけで再開できる範囲

このリポジトリには、提出サイトのソース、メールの書式、Gmail→Google Sheets監視のソース、公開・運用手順が入っています。したがって、新しいClaude Code / Codex / 開発者は、クローン直後から以下を再開できます。

- 提出サイトのUI・課題カード・提出メール本文の変更
- `npm run verify` によるビルドと画面ロジックの検証
- Apps Scriptのロジックのレビュー・修正・新規環境への再構築
- `main` へのpushによる、接続済みVercel本番の更新

一方、公開リポジトリに本番の認可情報を置くことは安全でないため、次はリポジトリだけから自動取得できません。

| 本番資産 | リポジトリ外に置く理由 | 引き継ぎ時に必要なもの |
| --- | --- | --- |
| Vercel環境変数 | 提出先メールなどの運用値 | Vercelプロジェクトへの権限 |
| Google Spreadsheet | 生徒の提出データ | 管理表への権限とID |
| Apps Script / Gmail | Google OAuthと時間トリガーがGoogleアカウントに属する | Script・受信Gmailへの権限 |

実運用をそのまま保守する担当者には、管理者が安全な経路で上記のアクセス権を渡し、ローカル限定の `ops.local.md` を埋めます。公開Gitに実値を書かないことが、この構成の前提です。

## 読む順番

1. `README.md` — 全体像と最短セットアップ
2. `AGENTS.md` — 作業規約と禁止事項
3. この文書 — 本番との差分・復旧手順
4. `docs/運用手順.md` — 授業運営・障害対応
5. `apps-script/README.md` — Gmail監視の構築

Claude Codeはリポジトリ直下の `CLAUDE.md` を読むことで、この順番と秘密情報の扱いを取得できます。

- 本番公開URL: `https://web-site-assignment-desk.vercel.app`
- GitHubの既定ブランチ: `main`
- VercelのRoot Directory: `app`
- Vercel本番更新: `main` へのpush
- 提出メール件名: `【WEB提出】課題ID｜学籍番号｜氏名`
- 本文の必須先頭行: `URL: https://...`

## 新規マシン / 新規セッションの開始手順

```sh
git clone https://github.com/rahiseko-alt/website-0917-asutra.git
cd website-0917-asutra
cd app
copy .env.example .env.local
# .env.local にはローカル検証用の提出先を設定（Gitへ追加しない）
npm ci
npm run verify
npm run dev
```

画面の見た目とメール生成はここまでで検証できます。実際にメールを送る試験は、提出管理表へ記録されるため、管理者の合意を得た専用テストアカウントだけで行います。

## 本番変更の標準手順

1. 作業前に `git status` を確認し、他者の未コミット変更を上書きしない。
2. `app/src/content.js` の課題IDを変える場合は、Google Sheetsの `PBL課題一覧` も同じIDにする。
3. `cd app && npm run verify` を実行する。
4. 差分を確認し、コミットして `main` にpushする。
5. Vercelの当該プロジェクトでProductionがReadyになったことを確認する。
6. 本番URLを開き、提出フォームが表示されるところまで確認する。

環境変数の変更はGit pushとは別作業です。Vercelの対象プロジェクトで `VITE_SUBMISSION_TO` を変更し、Productionを再デプロイします。値はブラウザのメール作成に使われるため、学校の専用提出アドレスを使います。

## Apps Scriptを本番へ同期する

`apps-script/Code.gs` をソースの正とします。Apps Scriptエディタへ貼り付ける運用でも構いませんが、継続開発するならclaspを使うと差分管理が安定します。

```sh
npm install --global @google/clasp
clasp login
cd apps-script
copy .clasp.json.example .clasp.json
# .clasp.json の <SCRIPT_ID> を管理者から受けた実値に置換
clasp pull
# リポジトリ版との差分を確認してから
clasp push
```

`clasp push` は実際のApps Scriptを更新します。push後にApps Scriptの実行履歴を確認し、必要なら `setupSubmissionDesk` を一度実行して権限とトリガーを整えます。トリガーの再作成は受信処理の重複を防ぐため、むやみに行わないでください。

## 復旧の判断

- **UIだけ壊れた**: `app/` を修正し、検証後にGit push。Google側には触れない。
- **メールが表に出ない**: `docs/運用手順.md` の障害表を先に確認。Gmail、実行履歴、`_障害ログ` をこの順で見る。
- **Google側を失った / 新年度に作り直す**: `apps-script/README.md` に従って新規Sheetと新規Scriptを作る。新しいIDはVercelやリポジトリではなく、管理者の `ops.local.md` に記録する。
- **Vercelの接続を失った**: VercelでこのGitHubリポジトリをImportし、Root Directoryを `app` に設定して環境変数を再設定する。
